### 🗂 第 8 张 · 要做"造车人"，不做"纯司机"
这张片子就一句话：要做造车人，不做纯司机。现在写程序，调个库、拼个接口，谁都能把车开起来——这是司机。但车发动机怎么响的、变速箱怎么咬合的，一概不知——车坏在半路就只能等拖。咱们物理系不一样：你们以后写的程序，是要贴着自己的仪器、自己的算法、自己那台跑得满头大汗的计算机去的。等拖车的人写不好控制程序。

### 🗂 第 9 张 · 做鸿蒙背后的造车人：为什么核心系统离不开 C 语言
为什么核心系统离不开 C？你看鸿蒙、Linux、Windows，最底下那层内核代码，C 语言写的占绝对大头。道理不神秘：操作系统要直接指挥硬件——内存哪个格子给谁、CPU 这一拍干哪件事——这种活既要离硬件足够近，又不能完全用 0 和 1 去写，C 正好卡在中间。上层的应用语言十年一换、 trendy 得很，可这一层二十年没换过主人。这就是这门课存在的理由。

导入课题，就看这一张排行榜——2026 年 7 月的。每年都有人说 C 过气了，你们自己看它掉没掉。先猜一把：现在第几？【等学生答】指屏幕：名次比大多数人的直觉靠前。为什么会这样？因为排行榜数的是'有多少活代码在跑'，而世界上跑得最久的那批代码——操作系统、数据库、嵌入式、编译器本身——底座全是 C。新语言在楼顶上开花，C 在地基里承重。

### 🗂 第 12 张 · 1.1 什么是计算机程序（一组指令 / p1）
翻到课本第一页，第一句话就是本章第一个定义，圈出来：程序——一组计算机能识别和执行的指令。三个词都不能少。'一组'：不是一条指令，是一串，有先后。'能识别、能执行'：这是人写不出来直接跑的东西——它得讲计算机的母语。定义后面还有半句狠话：计算机的一切操作都由程序控制，离开程序，它一事无成——再贵的电脑，没程序就是一块发热的铁。顺手辨个疑：菜谱算不算程序？像——也是一组步骤；差在哪？【等学生答】执行者不对，菜谱是人执行的，人看得懂'少许盐'，计算机看不懂——它要的是精确到它能识别的指令。

### 🗂 第 13 张 · 1.2 什么是计算机语言（三阶段 + 定义）
计算机语言，课本定义：人和计算机交流信息的、计算机和人都能识别的语言——注意'都能识别'四个字，翻译官的本职。它的发展走了三个阶段：第一代机器语言，0 和 1 串成的指令，计算机的母语；第二代符号语言，用英文字母和数字给指令起小名，这叫汇编；第三代高级语言，写法接近人话和数学式子，C 就是其中之一。高级语言内部还分两支：面向过程和面向对象——C 站在面向过程这一支，先把事情一步一步捋顺了，再谈别的。

### 🗂 第 14 张 · 0 和 1 的物理底座（晶体管电平 + 双稳态 + 穿孔纸带）
前面说机器语言是 0 和 1——物理上这是个什么？看图：一只晶体管当开关，导通，输出高电平，五伏，记作 1；截止，低电平，零伏，记作 0。旁边这个问题问得好：为什么只用双稳态？三档、四档不是能存更多信息？——因为中间态一碰噪声就翻车，电磁干扰一来，'1.5 伏'到底是 1 还是 2 谁也说不准；只用两个稳态，容错余量最大。这就是**用状态数换可靠性**，你们模电里施密特触发器迟滞回线，同一个思想。下面这张打孔纸带是老古董：有孔是 1、无孔是 0，程序真用纸张'存'过的年代。

### 🗂 第 15 张 · 三代语言升级链（高级→编译→汇编→机器→硬件执行）
把刚才的话画成一条链：最顶上高级语言，面向人类逻辑，好处是通用、可移植；C 语言在这层的确立，靠的是把结构化范式钉死了——程序就允许三种写法：顺序、选择、循环，这是它给整个行业留下的规矩。往下一格'编译'，高级代码翻成汇编指令；汇编语言用 ADD、SUB 这些助记符替掉二进制，好读一点，但深度依赖 CPU 指令集，换个 CPU 就不通用；再一格'汇编'，助记符变成纯 0101；机器语言直接驱动门电路和 ALU，硬件开跑。从上到下两次翻译、一个执行。

### 🗂 第 16 张 · 从源程序到运行结果（程序员/编译系统/OS/硬件 泳道图）
一张泳道图把刚才的链条落到人头上。第一条道，程序员：写 .c 源文件，动脑和打字的是人。第二条道，C 编译系统，里面两个工种：编译器干语法检查、代码优化，把源程序翻成 .obj 目标程序——注意，这时候还不能跑；链接器干组装，把你调用的 printf 这类系统库函数拼进来，生成 .exe 或者 Linux 下的 ELF——这才叫可执行程序。第三条道，操作系统：分配内存、创建进程、调度 CPU。第四条道，硬件：取指、解码、运算，最后把结果写到屏幕。记住一句话：**编译是翻译，链接是组装**——考试就爱在'连接'这个环节挖坑。

### 🗂 第 19 张 · C 的出身：为 UNIX 而生
C 语言最初的任务只有一个：给 UNIX 操作系统提供一种工作语言。没有改变世界的宏愿，就是贝尔实验室那几位工程师嫌汇编写系统太痛苦，需要一门'离硬件近、又不用天天数 0 和 1'的语言——C 就是这么出生的。有意思的在这儿：它是个工具出身，先干活后成名，跟很多冲着'重新定义编程'去的语言路线完全相反——越是解决具体问题的，活得越久。

### 🗂 第 23 张 · C99 的 37 个关键字全名单（英语虚词类比）
屏幕上 37 个 C99 关键字，我念一串你们感受下：auto、break、case、char、const、continue、default、do、double、else、enum、extern、float、for、goto、if、int、long……是不是有几个已经眼熟？眼熟就对了，这门课它们会反复出现。注意最后仨：_Bool、_Complex、_Imaginary，都带下划线打头——带下划线的是标准给自己留的专用通道，你写程序别起这种名。这些词是**征用词**，语言本身占用的，以后不能拿来当变量名——这条规矩第 3 章正式讲，今天先知道有这回事。

### 🗂 第 24 张 · 9 种控制语句（条件3 + 循环3 + 跳转3）
C 的控制语句，课本给了九种，按功能分三堆。条件判断三句：if、if-else、switch-case——让程序会拐弯。循环三句：for、while、do-while——让程序会重复。跳转三句：break、continue、return——让程序会撤退和交差。声明在前：这九种今天一个都不深讲，第四、五、七章一人一章领走；现在只要求认脸，别把 do-while 和 while 的关系现在掰扯——那是第五章的重点。到这，C 的家底：出身、标准、词表、控制语句，全过完。还剩最后一块拼图——它凭什么流行五十年。

### 🗂 第 25 张 · 特点① 运算符丰富（34 种 / p3）
特点一：运算符丰富，三十四种。什么叫运算符？干加工的符号——加减乘除是，比较大小是，连括号、赋值号、强制类型转换都被算作运算符。这条'赋值号是运算符'值得多说一句：数学里的等号是个关系，两边必须相等；C 里的'='是个动作，把右边的值搬进左边的格子——它当然算运算。这个误会第 3 章会正式掰，今天先知道有这回事。运算符多，是因为 C 要加工的数据种类也多。

### 🗂 第 26 张 · 特点② 数据类型丰富（p4）
特点二：数据类型丰富。整型、浮点型、字符型这些基本的先列着，后面还有数组类型、指针类型、结构体类型、共用体类型；C99 又添了复数浮点、超长整型 long long、布尔 bool。链表、树、栈这些数据结构课里的花样，全靠指针类型撑起来。这条特点我教你们换个读法：**这就是本课程的目录**——刚才念的每个名词，对应后面某一章；今天不用懂，混个脸熟，学到那章时回想今天这页就行。

### 🗂 第 27 张 · 特点③ 结构化控制语句 + 函数模块化
特点三：具有结构化的控制语句。刚才第 24 张数的那九种——if 系、循环系、跳转系——就是这条特点的实物清单。再加半句：C 用**函数**当程序的模块单位，大程序切成小块，每块一个函数，拼起来跑。所以课本敢下断言：C 是完全模块化和结构化的语言。

### 🗂 第 28 张 · 特点④ 语法限制不严、自由度大
特点四：语法限制不太严格，程序设计自由度大。举两个课本原例：数组下标越界，它**不检查**——你写了不该碰的格子，编译器一声不吭；变量类型用得灵活，整型量和字符型数据可以通用。听着像缺点？确实是把双刃剑：C 的设计哲学是'别替程序员做主'——每次数组访问都查一遍越界，性能要掉一截，它把选择权留给你，出了事也你自己扛。这话不是空谈，第六章写数组时你们会亲眼见到越界是什么现场。

### 🗂 第 29 张 · 特点⑤ 直接访问物理地址、位操作（高级+低级双身份）
特点五，C 的看家本领：允许直接访问物理地址，能进行位操作，可以直接对硬件下手。回忆第 9 张鸿蒙那张片子——核心系统为什么非 C 不可？根子就在这条：它一边有高级语言的好写，一边保留低级语言贴硬件的本事，双重身份。别的语言要么高高在上碰不到硬件，要么趴在硬件上换台机器就废；C 卡在中间，两头都够得着。而且注意——它虽然能贴硬件，却**不绑定**任何一款硬件。

### 🗂 第 30 张 · 特点⑥ 可移植性好
特点六：用 C 写的程序可移植性好。C 的编译系统本身做得简洁，很容易搬到新机器上；新平台上，标准链接库里大部分功能直接就能编译，源代码不用动。所以'几乎所有计算机系统都支持 C'不是恭维，是事实——从单片机到超算，都有 C 的编译器。为什么偏偏是 C 做到这点？把上一条和这条连起来看：核心极简，所以哪儿都放得下；能贴硬件，所以什么机器都伺候得了。

### 🗂 第 31 张 · 特点⑦ 目标代码质量高、执行效率高
特点七：生成的目标代码质量高，程序执行效率高。前面'贴硬件''不背包袱'那几条，红利全兑现在这——同样的活，C 写的程序跑得飞快，占的资源还少。这也是到今天为止，性能敏感的地方还是 C 的地盘的原因。好，七条特点到齐。我发现没有？这七条翻来覆去说的是同一件事：**C 信任程序员**——给你贴硬件的权力、给你自由排版的空间、也给你自己背锅的责任。

### 🗂 第 34 张 · 例 1.1 代码 + 函数体标注（｛｝内为函数体）

### 🗂 第 35 张 · 例 1.1 代码 + int / return 0 标注（返回整型）

### 🗂 第 36 张 · 例 1.1 代码 + #include / printf 标注（头文件 + 输出函数）
第一行，#开头的这个叫预处理指令，include——包含。stdio 是 standard input & output，输入输出，加个点 h，是 header，头文件。这行的本职：**事先告诉编译器，我后面要用库里的输出字符函数**——不告诉，编译器不认识 printf，直接给你报错。那 printf 自己呢？标准输出函数，活儿是把引号里的内容原样送到屏幕。插一句上节课的伏笔：printf 的实现根本不在你这五行里，它躺在系统库中——链接时被组装进来，还记得吧？'链接是组装'，组装的就是它。

### 🗂 第 37 张 · 例 1.1 代码 + \n 换行符 + main 结束标注
最后一个小零件：字符串末尾的 `\n`，换行符。反斜杠打头、n 收尾，合起来是一个字符的事：输出完这句话，让光标翻到下一行行首。不加它会怎样？也能跑，只是后面再有输出会全挤在同一行。注意它是**一个**记号管一件事，别念成'反斜杠 n 两个字母'。到这，五行代码从头到尾全认齐了——#include 报菜名、main 起跑线、函数体干活、return 0 交暗号、\n 管排版。

### 🗂 第 38 张 · 例 1.1 代码 + 加载函数库 / 分号标注
跑之前补两处操作细节。第一，程序运行时要**加载函数库**——printf 的本尊在库里，这时候才被拼进来干活，跟上周说的组装对上了。第二，看图上标红的：printf 这行末尾那个分号，**不写，编译就报错**。为什么？C 编译器判断一句话结束只认分号——它不管你换不换行，一行的写法只是给人看的礼貌。以后你们第一个深夜报错，八成就是漏了个分号，别慌，先看它。

### 🗂 第 39 张 · 例 1.1 运行结果（输出 This is a C program.）
看结果：黑底白字一个运行框，里头就一行——This is a C program。跟题目要求一个字不差，'原样输出'兑现了。这就是你们这学期第一个跑起来的程序，别看它只有一句话，五脏俱全：头文件、主函数、函数体、库函数调用、返回退出，前几页掰的零件全在这跑通了。我带你们课代表给这个程序鼓个掌——不丢人，五十年前的程序员看到这行字也这个心情。

### 🗂 第 40 张 · C 语言的两种注释（// 单行 / /*…*/ 块）
注释，C 语言允许两种写法，课本上就这两条。第一种，两条斜杠 //，管一行——可以单独占一行，也可以跟在代码右侧，代码照跑、你看的说明写在后头。第二种，/* 开头 */ 结尾，块式——中间想包几行包几行，注意必须成对，开了不关，编译器把你后面全当废话。本质一句话：注释在编译时整段被剥掉，机器一个字不看，专门写给翻你代码的人——包括三个月后的你自己。补一句：// 这种写法是 C99 才收编的，特别老的教材只教块式，咱们按 C99，两种都合法。

### 🗂 第 41 张 · 随堂题②（源程序文件后缀 / 雨课堂单选）
雨课堂第二题，单选：C 语言源程序文件的后缀是什么？A 点 EXE，B 点 OBJ，C 点 C，D 点 ASM。二十秒。【等答题约30秒】答案 C。你们发现没有，这四个选项没一个是瞎编的——EXE 是可执行成品，OBJ 是编译完的半成品，ASM 是汇编语言的文件，唯独点 C，是你亲手写、亲手存的那个源文件。

### 🗂 第 42 张 · 随堂题③（源程序转成可独立运行 = ？ / 雨课堂单选）
第三题，这题有坑，先读两遍再答：将 C 语言的源程序转换成可以在机器上独立运行程序的过程，称为——A 解释，B 编译，C 连接，D 汇编。三十秒。【等答题约30秒】答案 B，编译。报 C 的同学别委屈，听我拆：'连接'确实也在流水线上，可它的活儿是把库里的零件**组装**进来，不负责'转换'——把一种语言的全文翻成另一种，这动作才叫编译。上节课泳道图送过口诀：**编译是翻译，链接是组装**——题目就考你这两兄弟分没分得清。回去把那句口诀在笔记旁边再补一道线。

### 🗂 第 43 张 · 随堂题④（程序从哪儿开始执行 / 雨课堂单选）
第四题，送分题兼埋雷题：C 语言程序从哪里开始执行？A 第一条可执行语句，B 第一个函数，C main 函数，D 包含文件里第一个函数。二十秒。【等答题约30秒】答案 C。雷在哪？B——'第一个函数'听着多顺理成章，可 C 不看书写顺序：你把辅助函数写在文件最上头、main 写在最底下，程序照样从 main 发车。文件里的排列是给编译器看的库存清单，执行路线只认一个起点：main。这三题连过，零件、工序、发车点全认齐了。

### 🗂 第 44 张 · 例 1.2 题干（求两个整数之和 / 3 个变量赋值）
例 1.2，求两个整数之和，算 123 加 456。看到这题别笑——你们确实会算，可'把会算变成让计算机替你算'是另一回事。课本给的思路就三条，你们对着屏幕在例题旁边圈出来：第一，设三个变量，a 和 b 用来存那两个整数；第二，sum 用来存和；第三，用赋值运算符把结果传给 sum。第三条注意——上节课特点①我埋过桩：'='在 C 里是个动作，把右边的值搬进左边的格子；今天它正式上岗。思路不复杂，拢共六行。

### 🗂 第 45 张 · 例 1.2 代码（先声明后使用 + 输出 sum is 579）
六行代码，比第一个多了三行，全在函数体里。第一行新的：int a, b, sum——一句话声明三个整型变量，逗号隔开，末尾分号收尾，这叫'领三个格子先报备'。后面三行依次干活：a 里放 123，b 里放 456，第三行 sum 等于 a 加 b——注意，这个'='不是数学等号，是个有先后的动作：先把右边 a+b 算出来，再把结果搬进左边的 sum 格子。图上标了四个字的规矩：**先声明，后使用**——你没报备过的名字编译器一律当陌生人。算完输出，屏幕上出的是 sum is 579。

### 🗂 第 46 张 · 例 1.2 代码 + printf 细节（%d 用 sum 的值替代）
盯住输出这行：引号里写的不是 sum is 579，是 sum is 百分号 d。这个 %d 是个坑位——运行时被后面那个 sum 的值替掉，579 填进去，屏幕才看到 579。所以一条输出语句两段分工：引号里是模板，文字原样打、坑位等着填；引号外逗号后面，是填坑的料。坑和料要一一对应：两个 %d 就得给两个值，给少了不错个位就报乱码——这是你们接下来一个月最常见的丢分点。类比一句：席位和人头要对得上。

### 🗂 第 47 张 · 例 1.3 题干（求两整数中较大者 / 用一个函数实现）
例 1.3，求两个整数中的较大者——听着像托儿所问题，可它是你们第一次'拆函数'。解题思路圈两道：第一，用一个函数来实现'求两数中较大者'这件事；第二，在主函数中调用这个函数，再输出结果。跟前两例的差别在哪？前两例所有活都在 main 一个函数里干完；这例开始分工——比大小这件专业的事，交给一个专门的函数。上节课特点③念过那句'用函数作为程序的模块单位'，当时只是念了句概念，现在看到实物了。

### 🗂 第 48 张 · 例 1.3 main 代码页（max 是给 main 干活的小弟）
这张图左右两块就是分工现场。左边 main：开头先把 max 的'档案'声明一句——它接收两个浮点数、返回一个浮点数，先报备；接着 scanf 从键盘读两个数进 a 和 b；然后一行关键代码，c = max(a, b)——这就是'派活'：把 a、b 交给 max，要结果；最后 printf 把拿到的 c 打出来。右边那块是 max 自己的定义，图上给它的话：我是 max 函数，我的功能是将 x 和 y 中较大的值返回给主函数。图上叫它'给 main 干活的小弟'——话糙理不糙：调用方不动手，动手的不调用。

### 🗂 第 49 张 · 例 1.3 程序执行顺序（动图）
动图来了，眼睛跟住箭头。第一跳，程序从 main 第一行起步，声明、读入，按部就班；第二跳，执行到 c 等于 max 括号 a 逗号 b 这一句——注意，控制权交接，箭头跳到右边的 max，同时把 a、b 的值递过去；第三跳，max 比完大小，把较大值交给 return——带着结果跳回来，落回刚才那句没执行完的地方；第四跳，main 拿到 c，接着输出、收尾。全程一个要点：不是 max 自己干完就跑了——**控制权是借出去又收回来的**，main 从头到尾是大管家，max 只是应邀上门干一票。这条路线在脑子里能放动画，函数调用这一章就算入了门。

### 🗂 第 50 张 · 例 1.3 完整代码（函数原型声明 + scanf 的 & 取地址）
完整代码拼起来了，从头扫一遍：#include；然后 main 里第一行不是可执行语句，是对 max 的**原型声明**——提前告诉编译器这个函数的样子：进两个浮点、出一个浮点；函数体内 scanf 读两个整数、赋值给 c、输出；main 关门之后，才是 max 的真定义：接收 x、y，比较，把大的 return 回去。这页最要紧的是 scanf 里那个 & 号——图上专门标了：**& 是取地址运算符**。为什么 printf 不加它 scanf 偏要加？因为分工不同：printf 只要'拿个值去印'，scanf 却要'往格子里填东西'——填就得知道门牌号，&a 就是把 a 的地址交给它。还有个小坑：格式串里两个 %d 之间是个逗号，那你键盘上就得按'8逗号5'回车——格式串里写了什么字符，键盘上就得照敲什么。三个程序到这儿全拆完了。

### 🗂 第 51 张 · 例 1.3 形参与实参（定义给形式，调用给实际）
最后一对概念，图上口诀写得好，念一遍再解释：定义函数时给的是**数据的形式**，叫形参；调用函数时传的是**实际的数据**，叫实参。max 定义里那两个 x、y，是占名的空位——形参；调用时递进去的 8 和 5——实参。拿招聘打比方：岗位说明书上写'要求两名熟练工'，那是形参；真被派去的那张三李四，是实参。两句补充：第一，赋值方向永远实参到形参，单向；第二，形参在函数里是个副本，怎么折腾都不回头改实参——这叫值传递，第七章拆函数时细说，今天认脸为止。

### 🗂 第 53 张 · 结构① 一个程序由一个或多个源文件组成（p9）
课间回来趁热拆架子。课本把 C 程序的骨架总结成了八条结构特点，今天逐条过。第一条翻到课本第九页，圈住：一个程序由一个或多个源程序文件组成。后面给了盘点——你们今天的三个例子，小程序往往就一个源文件；例 1.1、例 1.2 各只含一个函数，例 1.3 含了两个函数，但三个例子都装在同一份文件里。先给你们交个底：这学期的作业全是'一个文件、一到几个函数'的形态，多文件拼工程是以后的事。

### 🗂 第 54 张 · 源文件的三部分（预处理指令 / 全局声明 / 函数定义）
一份源文件拆开，三层内容。第一层，预处理指令，#打头的，include 这种——你们已经天天在写。第二层，全局声明——在函数之外声明的数据。注意这条你们还陌生：今天的三个例子里一个都没有，因为变量全声明在函数体内；写到后面章节会有'声明在函数外面'的东西，先认个位置。第三层，函数定义——每个函数实现一定的功能，这是大头。拿例 1.3 对号：第一行是指令，main 那块和 max 那块都是函数定义，全局声明空着。还有句要紧话：这三部分在文件里的**书写顺序**，预处理指令在最前——声明在前使用在后，全局如此局部也如此，这条规矩后面报错时你们会反复重温。

### 🗂 第 55 张 · 结构② 函数是 C 程序的主要组成（main 只能有一个）
第二条：函数是 C 程序的主要组成部分。四小条我念你们圈：一个 C 程序由一个或多个函数组成；必须包含一个 main 函数，而且**只能有一个**；每个函数实现一个或几个特定功能；被调用的函数可以是库函数，也可以自己编。插一句大实话：你们以后真手滑写了两个 main，编译那关能过，链接直接爆红——因为起跑线只能画一条，编译器不知道从哪发车。这四条里'自己编函数'你们已经在例 1.3 干过了——max 就是自己编的。

### 🗂 第 56 张 · 小游戏：让模块回家（funcourse 链接）
屏幕上是链接，扫码或手敲都行。规则一句话：程序被拆成了模块碎片，顺序打乱了，你们负责把它们拖回原位——谁先拼完举手。三分钟，开始。【等学生操作约3分钟】……都拼得差不多了，请刚才最快的那位说说：哪块你最先放错？为什么？……说得到位。这个游戏考的就是刚才第二条那句话的意识：每个函数有自己的岗位，功能不越位——预处理指令不能站到函数体里去，main 不能站到别人后面去。

### 🗂 第 57 张 · 结构③ 函数 = 函数首部 + 函数体（int main(void)）
第三条，把一个函数切两段：第一行叫**函数首部**，剩下的叫函数体——注意这两个词别登错记：函数体你们在例 1.1 那页见过，就是那对花括号；今天上面又多了个'首部'——就是 int main 括号那一行。这页还有个新东西：无参函数，括号里写什么？课本给了两个合法答案：写 void，或者干脆留空——int main 括号 void，或者 int main 空括号，都对。你们从例 1.1 看到现在，括号里一直空着——那也行，不过建议写个 void，它是在声明：'我不是忘了填，我是真不接收参数'——给未来的自己留注释。

### 🗂 第 58 张 · 函数体的两部分（声明部分 + 执行部分）
函数体内部再切两刀。第一刀，声明部分——两件事：把本函数要用的变量定义出来，把本函数要调用的其他函数声明在先——例 1.3 开头那句 max 原型声明，干的就是这个。第二刀，执行部分——若干条语句，真正操作的步骤。这页最有价值的是角落里那句小字：**可以没有声明部分**。想一个现成的例子马上能举——max 的函数体里一句声明都没有，上来就比较、就 return，因为 x、y 从首部就递进来了，不需要再备料。

### 🗂 第 59 张 · 图：声明是备料、执行是炒菜（正例 say_hi / 反例 calc 未声明报错）
这张图把刚才那层关系画成做饭：声明部分是**备料**——把要用到的东西先摆上台面；执行部分是**炒菜**——真看火候下锅。左边正例 say_hi：声明栏空的，直接 printf——合法，为什么？人家不需要备料，一口现成的锅就在库里，张嘴就喊。右边反例 calc：上来就 a 等于 10，a 是谁？没声明——编译器当场报错，图上红字标得清楚。这就是刚才那句'先声明后使用'的执法现场。给物理系的同学补一层：编译器得先知道这个格子占几字节、怎么摆，才能把后面的代码都安顿好——C 把这件事定在编译期；你们要哪天碰了 Python 那种运行时现搭的，回头再对比着理解。

### 🗂 第 60 张 · 空函数（void dump() { }）
刚才的极端问题这页给答案：void dump，括号，然后一对紧挨着的花括号——中间啥都没有。这叫**空函数**，完全合法。两件事：第一，void 打头——回忆例 1.1，int 是'要带回一个整数'，void 就是'什么都不带回'，正好一对反面；第二，体里空的——刚才说过可以没有声明部分，执行部分空着也拦不住，合法。那你写个什么都不干的函数图什么？【等学生答】占位——大工程里先把岗位挂上，名字、接口都定好，内容以后再填；你们马上就会遇到：实验模板里好几个空函数等你填。

### 🗂 第 61 张 · 图：函数像加工车间（do_later(){} 占位 / 漏函数体反例 / 自顶向下）
图上把函数比作**加工车间**：门牌是函数名，原料从参数口进，成品从返回值口出——昨天……不对，今天早些时候那个 max 车间，进两枚浮点数，出一枚较大值，标标准准一个加工单元。中间栏是把空函数接到工程里：do_later 先挂个空车间占位，合法——刚才说的占位，图给画实了。右边反例注意看：只写了首部再加个分号，车间没了——这不叫'简化版'，这叫黑户：名片上写着有个车间，地上一块砖都没垒，编译器当场点收报错。底部八个字先圈住：**自顶向下，逐步分解**——大活拆成车间，车间里再排工序。这是后面整章讲函数时的魂，今天先把图看懂。

### 🗂 第 62 张 · 结构④⑤ 从 main 开始 + C 语句完成操作、书写自由
两条并一页。第四条，程序总是从 main 函数开始执行——这句熟吧？随堂题④刚拿它考过你们一遍，当时说的'发车点'，课本原文在这。执行完 main 就结束——不管你把别的函数写在前写在后。第五条，C 对计算机的操作由一条条 **C 语句**完成——后面的章节里它们逐个登场；这页的重点是后半句：书写格式**比较自由**——一行可以写几个语句，一个语句可以分写在几行上。但课本紧跟半句：为清晰起见，**习惯上每行只写一个语句**。这半句我要重重地画——自由是权利，清晰是选择：编译器只看分号，可帮你改 bug 的队友只看你排版。

### 🗂 第 63 张 · 图：main 是超市唯一入口（正例每行一句 / 反例挤一行 / Clang-Format）
看图：左边正例，一个语句一行，清单一样清爽；右边反例，所有代码挤成一行——你们猜编译器什么态度？照单全收，能编译能运行——因为它只认分号断句，换行是给你们看的。这就是刚才'自由'的实盘：语法上自由，可读性上自己看着办。图上那个比喻直接用：main 像超市**唯一入口**——顾客只能从这门进，对应'执行从 main 开始'；货架怎么摆是书写自由，结账凭小票——小票就是分号。右下角给了解药：Clang-Format 这类格式化工具，一键把挤成一行的代码排回每行一句——原理就建在'排版不是语法'上，所以机器敢替你们排。

### 🗂 第 64 张 · 结构⑥⑦⑧ 分号必须有 + C 不提供输入输出语句 + 应有注释
最后三条，一页过完。第六条，声明和语句末尾必须有分号——例 1.1 那页已经现场实测过：漏了，报错。第七条最有意思，圈住慢慢读：**C 语言本身不提供输入输出语句**——什么意思？printf、scanf 你们用得理直气壮，它们的户口根本不长在 C 语法里，是**库函数**——标准输入输出库提供的。回想去例 1.1 那页说的'链接是组装'：输入输出是外接设备，不是语言自带的器官——C 只定了接口，IO 全家都在库里。这条也是考题宠儿，选择题就爱问'C 语言提供的语句包括不包括输入输出'——不包括。第八条，程序应当包含注释——刚才讨论时有同学说'注释是今天的易错点'，写代码不写注释，三个月后自己都不认。

### 🗂 第 65 张 · 图：分号与标准库（漏分号报错 / stdio.h 提供 IO / 其他语言换行判边界）
结构部分最后一张图，三栏。左栏反例：int a 等于 1，后面没分号——报错，红字标得明白，而且编译器报的行号还可能往后躲——错在一行、报在三行的痛，你们很快就会懂。中栏把第七条展开：C 不内置输入输出，stdio.h 带头的标准库提供——你们每份文件开头那行 #include，就是在拉这根外接水管。右栏是彩蛋对比：Java 继承了分号传统；Python、Go 靠换行判句子边界——以后你们学第二门语言，这是第一个肌肉记忆冲突点，提前打个招呼。到这里，八条骨架全部过完，1.4 整节收官。

### 🗂 第 66 张 · 1.5 运行 C 程序的步骤与方法（四步 + 小游戏链接）
1.5，运行程序的步骤，四步清单，对照课本上的图 1.2 看：第一步，上机输入和编辑源程序，得到 .c 文件；第二步，编译，得到 .obj 目标文件；第三步，连接，把库里的零件拼进来，得到 .exe；第四步，双击运行，拿到结果。这页其实是把随堂题②和③连成了一条流水线——从 .c 进去、.exe 出来，中间那刀叫编译，拼零件的叫连接——当时分开考，今天串成线。另外两件事：附录 A 里有 VC++ 6.0 里每一步点哪个菜单的图文教程，实验课用；页底这个游戏《C 程序诞生记》把四步做成了关卡，课后玩，比刷题上瘾。

本章最后一节，1.6，程序设计的任务。第一条就讲分析问题：对接手的问题要认真分析——四小条圈住：研究所给的条件，分析最后应达到的目标，找出规律，选择方法。给你们换个熟悉的场：物理实验任务单发到手上，'测重力加速度'——你们第一件事不是抓仪器，是先盘：手里有什么器材——条件；要求测到几位精度——目标；然后才选自由落体还是单摆——方法。写程序同构：例 1.2 要是上来就敲输出语句，你会发现连要几个变量都没想好——先把'三个变量一个赋值'列清楚，六行码三分钟写完。一句话：**先想清楚再动手**——你们以后一半以上的返工，都是题没读完就升键盘。

### 🗂 第 68 张 · 1.6 六步全图（含金句：结果对了程序未必对）
六步全图，从头念一遍给你们串线：一，问题分析——刚讲完；二，设计算法——解题的方法和具体步骤，下一章整章讲这个；三，编写程序——今天三例的手艺；四、编辑编译连接——刚才 1.5 的那四步；五，运行程序、分析结果；六，编写程序文档——就是把说明书写齐。重点在第五步，课本送了两句话，我念慢一点：**结果错了，程序肯定错；结果对了，程序未必对**。前一句废话都没有；后一句是整章最值钱的一句话。坐实它：例 1.3 求较大者，你拿 8 和 5 测，出 8，皆大欢喜——可程序真对了吗？万一它把比较写反了，你换 5 和 8 测就穿帮；还有两数相等的边界——测一组就发榜的程序，和测三组才肯收工的程序，差的不是运气，是专业。你们实验报告里'用多组数据验证'问的就是这件事。六步走完，本章正课到此。
