# 多文件工程 · 分步编译示例(大一版)

这是一个**最简单的多文件 C 程序**,教你两件事:

1. 为什么、怎么把一个程序**拆成多个文件**;
2. 多个文件时,编译器是怎么**分步编译 + 链接**成一个可执行程序的。

---

## 一、文件结构

```text
multifile_demo/
├── calc.h     # 头文件:只放"函数声明"(相当于菜单,告诉别人有哪些函数可用)
├── calc.c     # 实现文件:写函数的"具体实现"(相当于后厨,真正干活)
├── main.c     # 主程序:调用 calc 里的函数
└── Makefile   # 一键分步编译脚本
```

**核心思想:声明与实现分离。**
`main.c` 只需要 `#include "calc.h"` 就知道"有 `add`、`max` 这两个函数可以用",
完全不用关心它们在 `calc.c` 里是怎么写的。这样代码好维护、能复用、方便多人协作。

> 小知识:包含**自己写的**头文件用双引号 `#include "calc.h"`;
> 包含**系统的**头文件用尖括号 `#include <stdio.h>`。

---

## 二、分步编译:三步走(重点!)

单文件时一句 `gcc main.c -o main` 就够了。但**多文件**时,标准的做法是"**先分别编译,再统一链接**"。

打开终端,`cd` 进本目录,依次敲:

```bash
# 第 1 步:把每个 .c 分别编译成 .o(目标文件)
#          -c 的意思是"只编译,先不链接"
gcc -std=gnu17 -Wall -g -c main.c -o main.o
gcc -std=gnu17 -Wall -g -c calc.c -o calc.o

# 第 2 步:把所有 .o 链接(link)成一个可执行文件
gcc main.o calc.o -o app

# 第 3 步:运行
./app
```

输出:

```text
x = 12, y = 5
x + y       = 17
max(x, y)   = 12
```

### 为什么要"分步"?

- **`.o` 是什么**:每个 `.c` 编译后生成的"半成品"叫**目标文件**(object file),里面是机器码,但函数地址还没最终确定。
- **链接(link)在干嘛**:第 2 步把多个 `.o` **拼**在一起,并把 `main.c` 里调用的 `add`/`max` 和 `calc.c` 里的实现"**对上号**",最终生成能直接运行的 `app`。
- **好处——省时间**:大工程里改了一个文件,**只需重新编译那一个 `.c`**,其它 `.o` 不用动,直接重新链接即可。这就是"分步编译"的意义。

> 常见报错 `undefined reference to 'add'`:说明**链接时漏了 `calc.o`**。
> 比如只写 `gcc main.o -o app` 就会报这个错——因为没人告诉它 `add` 在哪实现。

---

## 三、用 make 一键完成(推荐)

上面的三步,`Makefile` 已经帮你写好了。直接敲:

```bash
make        # 自动完成"分步编译 + 链接",生成 app
./app       # 运行
make run    # 等价于:先 make 再运行
make clean  # 清理:删掉 app、main.o、calc.o
```

`make` 聪明在:它会看**谁改了**,只重新编译改过的文件,没改的直接跳过。

---

## 四、⚠️ 注意:这个 demo 别用 F5 运行

根目录 `.vscode` 里的运行按钮(F5)是**"只编译当前单个文件"**的配置。
多文件工程如果只编译 `main.c`,链接时会因为找不到 `add`/`max` 而报错。

**所以本 demo 请用上面第二、三节的 `gcc` 命令或 `make` 来编译运行。**

---

## 五、动手改一改(练习)

1. 在 `calc.h` 里声明一个新函数 `int min(int a, int b);`
2. 在 `calc.c` 里实现它(求较小值)
3. 在 `main.c` 里调用 `min(x, y)` 并打印
4. 敲 `make clean && make && ./app` 看结果

改完能跑通,你就真正掌握多文件工程啦!🎉
