## 一、这个环境有多"通用"?先搞懂 C99/C11/C17/C23

很多同学一看到"C99、C11、C17、C23"就慌:**是不是每个版本都得学一遍?学不会怎么办?**

**答案:完全不用,学一个就够,而且这个环境全都支持。** 下面用大白话讲清楚。

### 1. 这几个名字是什么?

它们是 C 语言的**"国家标准"发布的年份代号**:

| 标准 | 全称 | 你可以理解成 |
|------|------|-------------|
| **C99** | 1999 年标准 | 教材主要教的版本,也是我们上课的重点 |
| **C11** | 2011 年标准 | 在 C99 基础上加了点"高级小工具" |
| **C17** | 2017 年标准 | **C11 的"修 bug 版",没有加任何新语法** |
| **C23** | 2023 年标准 | 又加了一些"写着更方便"的小功能 |

### 2. 最关键的一点:新版本"向下兼容"老版本

这是理解一切的核心 👇

> **老标准写的代码,在新标准下原样就能编译、正常运行;反过来才会出问题。**

打个你天天遇到的比方:

- 📱 **新版手机系统能装老 App**:安卓 14 能正常运行给安卓 9 写的软件,但你不用为了"升级"去重写它。
- 📄 **新版 Word 能打开老文档**:Word 2021 能打开 .doc 老文件,内容一个字都不丢。

C 语言标准也是这个道理:

- 你用 **C99** 写的代码 → 拿到 **C11 / C17 / C23** 编译器下 → **照样跑,不用改一个字**。
- 所以"只懂 C99"根本不叫短板,C99 是地基,后面的版本只是在这个地基上"锦上添花"。

### 3. 那 C11/C17/C23 到底多做了什么?(了解即可,不影响上课)

- **C11**:加了泛型宏、多线程、带边界检查的函数等——**初学阶段基本用不到**。
- **C17**:**纯粹是修复 C11 的 bug,一个新语法都没加**。记住一句话:`C17 ≈ C11`。
- **C23**:加了几个"方便写法",例如:
  - `nullptr`(更安全的空指针写法)
  - `bool` 直接当关键字用(以前要 `#include <stdbool.h>`)
  - 二进制字面量 `0b1010`(直接写二进制)

  这些都是"锦上添花",**你完全可以在学会 C99 之后,哪天有兴趣了再顺手了解一下,几分钟的事**。

### ✅ 一句话总结

> **上课按 C99 学就够了;这个环境底层用的是 `-std=gnu17`(C17 档,比 C99 更新、又极其稳定),所以你写的 C99 代码百分百能跑,还能顺便兼容教材里偶尔出现的更新写法。学一个版本,通吃四个标准——这就是它"通用且强大"的地方。**

## 二、快速开始:怎么打开这个环境?

1. 登录 [Cloud Studio](https://cloudstudio.net)。
2. 点击 **「从 Git 仓库导入」**。
3. 粘贴本仓库地址:`https://github.com/brookecoming/cloudstudio_c99_env.git`。
4. 等待环境自动启动(第一次会稍慢,属正常)。
5. 打开 `main.c`,点右上角 **▶ 运行按钮**,或按 **F5**,就能看到输出。

## 三、三种运行方式(按习惯任选)

### 方式 1:点运行按钮 / 按 F5(最常用)

打开任意 `.c` 文件,点右上角 **▶** 或按 **F5**,自动编译并运行,结果显示在下方终端。

### 方式 2:F5 断点调试(想一步步看程序怎么跑)

1. 在代码行号左侧点一下,出现红点(断点)。
2. 按 **F5**,程序会在断点处停下。
3. 用调试工具栏的"单步跳过 / 步入 / 继续"逐行执行,左侧能实时看到每个变量的值。

> 调试是学编程的"透视眼",强烈建议早点用起来。

### 方式 3:终端敲命令(进阶,理解编译过程)

打开下方终端,输入:

```bash
make        # 编译,生成可执行文件 main
./main      # 运行(Linux 环境要加 ./)
make clean  # 清理,删掉生成的 main
```

也可以直接用 gcc 手动编译单个文件:

```bash
gcc -std=gnu17 -Wall -g main.c -o main
./main
```

### 附:导入仓库后,一键装扩展、调出运行箭头 ▷

本地 VSCode 里编辑器右上角那个 **▷ 运行箭头**,是**扩展**画的,不是仓库配置画的。
本仓库已通过 `.vscode/extensions.json` 把需要的扩展设为**工作区推荐**:

1. 导入仓库后,IDE 一般会**弹出提示**或在扩展面板**高亮"推荐扩展"**,点「安装」即可;
2. 若没弹提示,就手动到扩展面板搜下面两个 id 安装:
   - `ms-vscode.cpptools`(C/C++:▷ 运行 + F5 断点调试)
   - `formulahendry.code-runner`(Code Runner:纯网页可用的 ▷ 一键运行)
3. 装完重载窗口,打开 `main.c`,右上角就有 **▷**,点它或按 F5 即可运行/调试。

> 说明:出于安全,IDE 不允许仓库"静默强制"装扩展,所以是"导入 → 点一下安装"这一气呵成,而非完全无人值守。
> `.vscode/settings.json` 已把 Code Runner 配成用 `-std=gnu17` 编译、并在终端运行(支持 `scanf` 输入)。

## 五、为什么本环境选 `-std=gnu17`?(正好卡在"甜蜜点")

有同学会问:标准这么多,为啥老师偏偏选 **gnu17**?因为它是"稳、新、通用"三者兼得的最佳平衡点:

- **稳**:C17 本质是 **C11 的"纯修 bug 版"**,没加任何新语法,所以它的稳定性和 gnu11 完全一样,不会莫名其妙报错。
- **新**:名字上贴近教材提到的 C17,底层用现代编译器档位,显得环境够新、够专业。
- **通用**:100% 向下兼容,你写的 **C99 教学代码一个字都不用改**照样跑。
- **`gnu` 前缀的好处**:相比严格的 `-std=c17`,`gnu17` 保留了 GCC 的常用扩展,不会因为"严格 ISO 模式"挡住个别常用函数,新手更不容易踩坑。

**那为什么不选别的?**

| 标准 | 为什么没选 |
|------|-----------|
| `-std=c99` | 够用,但偏"保守";严格 ISO 模式偶尔会挡住个别常用写法 |
| `-std=gnu11` | 一样稳,只是名字不如 gnu17 贴近教材的"新" |
| **`-std=gnu17`** | ✅ **就它**:稳(等同 C11)+ 新(贴近 C17)+ 通用(兼容 C99) |
| `-std=gnu23` | ⚠️ 云端 gcc 13 不认 `gnu23` 这个名字(要写 `gnu2x`),且 C23 支持不全、还把 `bool`/`nullptr` 变成了关键字,容易冲突 → 有编译失败风险,教学也用不上 |

> 一句话:**gnu17 = gnu11 的稳定性 + 更现代的名字,零风险,所以"正好"。**

### 想自己切换标准试试?(进阶)

把编译参数改一下即可:

- 改 `.vscode/tasks.json` 里 `args` 中的 `"-std=gnu17"`;
- 或改 `Makefile` 里 `CFLAGS = -std=gnu17 ...`。

可选值:`-std=c99`、`-std=gnu11`、`-std=gnu17`、`-std=gnu2x`(C23 实验档,取决于 gcc 版本)。

> 提醒:切换标准只是"尝鲜"。**平时练习和作业,保持默认的 gnu17、写 C99 风格的代码最稳妥。**

## 七、常见问题(FAQ)

**Q1:我写的代码在别处能跑,在这里报错?**
先检查是不是漏了 `#include`,或用了非标准函数(如老教材里的 `conio.h`、`getch()`、`clrscr()`——这些是上古 Turbo C 的东西,现代 Linux/gcc 环境不支持,和标准无关)。

**Q2:`make` 报错 `missing separator`?**
说明 `Makefile` 里命令行开头的缩进被改成了空格。**Makefile 的命令行必须用 Tab 键缩进**,不能用空格。

**Q3:中文输出乱码?**
本环境是 Linux + UTF-8,一般正常。若乱码,确认源文件以 UTF-8 编码保存。

**Q4:一定要联网吗?**
是。Cloud Studio 是云端环境,编译运行都在云上完成,需要联网,但对你电脑配置几乎没要求。
