# PPT Diagram Maker（课件配图生成）

把**一段文字 / 一个教学概念**变成**能直接插进 PPT 的图**。与 `textbook-code-extractor` 分工：那个从教材截图提取可编译 `.c` 例题代码；**本技能只产"某一页课件要看的图"**。

## 交付路径：手写 SVG → sharp PNG → 直插 PPT（唯一默认）

自 2026-10 起**只走这一条**：手写矢量 `xxx.svg` → sharp 转高清 `xxx.png` → 用 python-pptx **直接插入 PPT**（满版或按需定位）。
**不再走"`.puml` 底稿喂豆包"**——豆包免费额度不长久、排版不可控，直出更省事、可常态化。

🔴 无论何种图，**内容（例号、逻辑、课本原句）必须准确**——这是本技能的存在意义。

## 🔴 质量红线（学生视角，每次必守）

1. **去教师腔 meta**：图里**绝不出现**"教学说明 / 备注 / 注 / 老师照着讲"这类只给老师看的标题或旁注。学生也会看这张图。
2. **看图知意**：任何解释文字，要让**只看图的学生**读懂"这里在讲什么、为什么"。像"少了一个"这种**讨论时的口语**不能直接上屏——要按课本把"到底少了哪一格、为什么不能省"讲清楚。
3. **例号 / 术语必核对**：涉及教材例题的图，例号（如 2.1/2.6/2.11/2.16/2.18）、"直到型/当型"、人名年份一律以课本为准，**不凭印象**。本地已有 `0_textbook_code/{章}/textbook/` 目录下的教材扫描页图（Glob 该目录取图，直接 Read 核对）。🔴 **课件上绝不写课本页码**——学生所用版次与本地扫描件版次不同、页码对不上，定位只用 §号/图号/例号。
4. 🔴**投影对比度·生死线**：教室投影仪会吞掉低对比与浅色，**字必须又大又黑**。（a）**正文/标签一律深色**：白底用近黑 `#1A202C`（最低 `#2D3748`）；**严禁用浅灰做正文**（`#718096`/`#A0AEC0` 这类只能给“几乎可忽略”的水印，投影到最后一排就消失）。（b）**深色底/色块内文字用纯白 `#FFFFFF` 加粗**。（c）**字号下限**：标题 ≥20、框标题 ≥16、正文/注释 ≥14（SVG 用 px；mindmap 靠 `FontSize`）。（d）**自检一句**：“打印成灰度、或投到教室最后一排，还读得清吗？”——读不清就加深色/加大字号，不得交付。整体 4:3 或宽幅横排；中文用 `Microsoft YaHei, PingFang SC, Segoe UI, sans-serif`。
5. **中文别变豆腐块**：PNG 生成后**必须用 Read 打开回看**，确认中文正常渲染，再交付。
6. 🔴**要像 PPT 课件、不像零散流程图**：这是幻灯片不是框线图。标题醒目居顶、主体居中、大留白、圆角柔和配色，可做成分区/色带/编号步骤的信息图式排版。**元素放不下时优先分行/分组/两侧均衡展开，字号是底线——宁可放大画布，绝不缩字硬塞一行**（实测：6 个框排成上下两行各 3 个 + 回边，远比挤成一行清楚美观）。
7. 🔴**【红线·投影基本素养】学生可见文字零小字**：投影仪本就发虚，**凡是呈现在学生面前的字一律要大**（正文等效 ≥18pt、绝对下限 ≥16pt，标题/框名更大）。**放不下就精简措辞或放大画布，绝不靠缩字硬塞**（反面教材：把长说明缩成图底看不清的小字）。区分两类内容：**思路、导引问题、关键解释 = 给学生看的 = 必须上屏（大字）**；**只有老师口播的详细展开/补充讲稿才放 PPT“演讲者备注”**。
8. 🔴**【红线·必须有思路/导引】PPT 不能只放一个光图**：每页除了图/骨架，**必须承载“思路线 / 导引问题 / 关键解释”之一**，让学生“看图知意”、知道该往哪想——否则满屏并列名词，学生像没头苍蝇。该解释的就得在 PPT 上解释清楚（用大字、精炼），**“我嘴上会讲”不等于可以不写**：学生课后要能对着这页回想起来。
9. 🔴**【红线·编译口径】课件上一律用课本的 VC++**：谭浩强第 5 版全篇以 **Visual C++（VC++6.0）** 为默认环境（表 3.4 明标“Visual C++ 环境下”）。课件图里凡涉及**字节数、有效数字、数值范围、`long double` 大小、常量类型判定**等编译环境相关的结论，**一律按课本 VC++ 口径画**，不把 GCC 的实测运行值或另一种编译器口径写上屏（措辞用“课本（VC++）”，不说“咱们用的 VC++”——机房实跑 GCC）。学生上机跑出的 GCC 差异属于 `.c` 注释与“演讲者备注”层面（见 `vc-vs-gcc.md`），**课件表面只保留课本那一个标准**。

## 存放与 Git

- 课件图存 `c99_env/0_textbook_code/{章}/slides/`（如 `02/slides/升级链.svg`）。
- `slides/` **不在 .gitignore 内**（只挡 `textbook/` 扫描件与 `*.pdf`）——这些是**老师原创课件，应正常入库**。
- 命名用**中文语义名**（`升级链.svg` / `三种基本结构.png`），一眼知道是什么。

## 工作流

复制这份清单跟踪进度：

```
- [ ] 1. 读懂用户给的文字/概念，确定图类型（升级链/对比表/流程图/N-S/结构图）
- [ ] 2. 涉及教材事实 → Read 本地 `textbook/` 目录扫描页图核对例号/术语（不凭印象、不写页码）
- [ ] 3. 手写 SVG（矢量、准确、学生视角、无教师腔）→ 存 slides/
- [ ] 4. sharp 转高清 PNG → Read PNG 回看验证中文没变豆腐块
- [ ] 5. 用 python-pptx 把 PNG 直插 PPT（换图=删旧图形状+drop 旧图关系防悬挂；新增页=add_slide+满版图+页码占位+移入放映序）→ 复验结构无悬挂
- [ ] 6. 交付 PNG 路径 + 已插页号；同步提词本/口播稿/PPT 备注三处
- [ ] 7. 删除临时 node/python 脚本，仓库干净
```

（🔴 只走 SVG→PNG 一条路；不再写 `.puml` 喂豆包。涉及教材事实一律 Read `textbook/` 扫描页核对例号/直到型当型。）

## 路径 A：手写 SVG → PNG

### SVG 要点
- 根元素带 `font-family="Microsoft YaHei, PingFang SC, Segoe UI, sans-serif"`。
- 箭头用 `<defs><marker>` 定义一次，各线 `marker-end` 引用。
- 框用 `<rect rx>` 圆角、`<text text-anchor="middle">` 居中；高亮框换强调色（如橙 `#FFF3E0`/`#ED8936`）。
- 尺寸按内容给足（如 `width="1260" height="300"`），留白别挤。

### sharp 转 PNG（关键工具链）
`sharp` 与 `pdf-parse` 已装在 TEMP，脚本**必须写在项目目录内**（项目外不可写），用 `NODE_PATH` 指过去：

```powershell
# 临时脚本 _tmp_svg2png.js 写在 c99_env/ 下，内容见下；然后：
$env:NODE_PATH = Join-Path $env:TEMP 'pdfx\node_modules'
Set-Location 'D:\clion_workspace\c99_env'
node _tmp_svg2png.js
```

`_tmp_svg2png.js`：
```js
const sharp = require('sharp');
const svg = 'D:/clion_workspace/c99_env/0_textbook_code/02/slides/升级链.svg';
const out = svg.replace(/\.svg$/, '.png');
sharp(svg, { density: 200 }).png().toFile(out)
  .then(info => console.log('OK ' + info.width + 'x' + info.height))
  .catch(e => console.log('ERROR=' + e.message));
```

- `density: 200` 出高清（实测 1260 宽 → 约 3500px），投屏/打印都够。
- 控制台打印的中文文件名可能乱码，那只是终端编码，**写入用的是 UTF-8 源里的正确名**，无碍。
- **转完必删脚本**（`DeleteFile`），别把 `_tmp_*.js` 留在仓库。

### 交付话术
> - `xxx.svg` ← 首选：PPT **插入 → 图片 → 此设备**，矢量无限放大不糊、颜色还能在 PPT 里再调。
> - `xxx.png`（宽×高）← 备用：老版本 PPT 或当普通图拖入。

## （已弃用）`.puml` 底稿 → 豆包

历史上曾支持"写 `.puml` 喂豆包美化"。**自 2026-10 起弃用**：豆包免费额度不长久、排版不可控，且手写 SVG 已能直出高质量图。遇到"要更精美"的需求一律靠**打磨 SVG**（配色/留白/分区/圆角/编号色带）解决，不再回退豆包。

🔴 沉淀下来的两条硬经验（画 SVG 时同样适用，过去写进豆包指令让工具自查、现由我出图前自查自改）：
- **交付前自检**：①例号/课本原句在不在、有没有错位漏标 ②文字够不够大且深色/纯白可读 ③思路导引那条在不在且最醒目 ④别把 `#颜色码` 当字画出来 ⑤投到最后一排还看得清吗——任一不达标就重画。
- **信息量大/要分层的图用色带分区**（横向串联=升级链；自上而下阶梯=重点分级；并列分区=对比/结构图），别把一堆并列名词硬挤一行；宁可放大画布也不缩字。

## （已弃用·仅存档）豆包指令内嵌协议 —— 现由我出图前自查，不再喂豆包

把"喂豆包的提示词"**直接写进 `.puml` 的块注释 `/' ... '/`**，紧跟在 `@startuml`/`@startmindmap` 下一行。这样**指令随文件走**：真正的 PlantUML 渲染器（plantuml4idea）把 `/' '/` 当注释**跳过不画**；豆包是 LLM，会读到并执行——用户只需把整个文件贴进豆包，不必再单独粘提示词。

**块首用 `[豆包指令·勿画进图]` 自标注**，让豆包明确这段不是图内容。固定字段顺序不变（方便识别）：`画面 / 排版 / 思路导引 / 文字 / 字号 / 配色 / 避坑 / 交付前自检 / 输出`。其中 **`避坑` 每图现填**（该图特有的例号、直到型/当型、人名原样等陷阱），其余可复用。注意块结尾必须是单独的 `'/`，后面别跟任何杂字符。

🔴**【回查前移】把人工核对项写成 `交付前自检` 字段**：过去出图后要用户自己回查（例号有没有错位、字够不够大、颜色码有没有被当字画出来……）——这些**一律前移进指令块**，命令豆包**交付前自查自改、任一不达标就重画**，用户拿到即成品、不必再人工盯。每个 `.puml` 的指令块**必带一条 `交付前自检`**，把该图最易翻车的点列成 ①②③ 勾选式清单。

模板：
```plantuml
@startuml 图名
/'
=================== [豆包指令·勿画进图] ===================
画面: PPT 课件幻灯片一页(4:3); 标题醒目居顶、主体居中、大留白、圆角柔和 — 要像课件信息图, 严禁挤成一团的流程图感
思路导引: 必须有一段“思路/导引问题/关键解释”上屏(这是本页的灵魂, 别只放光图), 做成底部通栏、字>=16 看得清; 只有更细的口播展开才进 PPT 演讲者备注
布局: 元素多时优先分行/分组/两侧均衡展开(如 6 框排上下两行各 3 个 + 回边), 连线细少清楚; 宁可放大画布也绝不缩字硬塞
页脚: 图里那段解释/注释做成横跨底部的通栏色带, 别挂在单个框下、别在一侧留大片空白; 整体紧凑居中
文字: 深色高对比 — 白底近黑 #1A202C, 严禁浅灰; 深色块内文字纯白加粗

配色: 沿用下方 skinparam/style 指定的颜色, 别自创浅色文字
避坑: {本图专属：要保留的例号、直到型/当型、不可改的课本原样人名等}
交付前自检(必做, 别等用户查): ①各例号在不在、有没有错位漏标 ②文字是否都>=16 且深色/纯白可读 ③思路导引那条在不在且最醒目 ④有没有把 #颜色码 画成正文 ⑤投到最后一排还看得清吗——任一不达标就重画再交付
输出: 只回一张美化后的图, 不要解释文字
==========================================================
'/
...图内容...
@enduml
```

用户贴豆包时补一句即可：**"严格按文件顶部 `/' '/` 里的[豆包指令]执行，那段不要画进图。"** 若豆包不认 mindmap 语法，回退到已验证的 rectangle 方框风格（见"常见图类型速查"）。

🔴**内容多别用 mindmap**：思维导图枝杈一多字就被挤小、投影根本看不清（实测）；**信息量大/要分层的课件图一律用 rectangle 色带**（横向串联=升级链；自上而下阶梯=重点分级；并列分区=对比/结构图），已验证豆包能渲清楚。mindmap 只留给枝少字短的极简概览。

## 口播稿 → PPT 演讲者备注（图的收尾一步）

用户把**已生成的课件图（PNG 成品图）发过来**，要一段“能张嘴念、自己贴进 PPT 备注”的口播稿时走本节。**图归图、稿归备注**：口播稿**不写进 SVG**（SVG 只装图内容），直接在对话里交付可照念的稿；正式回填走 `ppt-course-builder/scripts/sync_notes.py`。

**六拍结构**（沿用 `textbook-code-extractor` / 规则 `textbook-c-code.md` 的【讲解过程稿】六拍，按“幻灯片”微调）：
1. **开场**：一句话点题或一个设问（抓注意）；
2. **这页在讲什么**：一句定位（如“这是全章开篇地图、不讲知识只说行程”）；
3. **主线/骨架**：先整体后局部，**绝不逐条念图上的字**（学生自己会看）；
4. **分区讲**：按图上区块说“是什么、为什么、**劲儿往哪使**”（地图/分级页尤其只给轻重）；
5. **关键强调**：本页最该让学生带走的那一句；
6. **收尾**：一句总结 + 抛一个提问顺势过渡下一页。

**必守细则**（同六拍红线）：①开场设问与收尾提问处加【**互动停顿：停 2~3 秒…**】标记；②**去教师腔**——不写“（老师照着念）”“讲课时可逐条说”这类 meta，稿子本身就是要说出口的话；③第一人称、口语、有起承转合，控制在 2~3 分钟；④**地图页/开篇页不用“讲”要用“说”**——像旅行前看行程表，只告诉学生哪儿使劲、哪儿扫一眼。

## 常见图类型速查

| 类型 | 结构要点 |
|---|---|
| 升级链 / 主线 | 若干圆角框横向串联 + 箭头标"升级n"，痛点写在框下方，关键环高亮 |
| 对比表 | 表头 + 分行对照（旧文件 vs 课本、直到型 vs 当型） |
| 传统流程图 | **严格按 ANSI 符号**：起止=圆角、处理/赋值=**矩形**、判断=**菱形**、输入输出=**平行四边形**（别把赋值画成圆角框） |
| N-S 盒图 | 无箭头、矩形嵌套、条件用对角表头分"成立/不成立"；while 顶栏"当条件"+循环体缩进 |
| 三种基本结构 | 顺序/选择/循环三框并列，各配一句 + 对应语法（语句 / if / while·for） |

## 何时触发 / 不触发

**触发**：用户给一段文字要“生成适合放 PPT 的图”“做个课件图/投屏图”“把这条链画出来”“更新这张幻灯片图”；**或发来一张已生成的课件图要“给这页配个口播稿/讲稿/写 PPT 备注”**（走上面“口播稿 → PPT 演讲者备注”一节）。
**不触发**：从教材截图提取可编译例题代码 → 走 `textbook-code-extractor`；纯代码/编译问题 → 直接答。
