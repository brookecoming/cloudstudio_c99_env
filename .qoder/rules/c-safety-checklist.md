# C 安全查错清单（答疑纠错时逐项扫描）

学生代码报错/求查错时，按此清单从头扫一遍，避免临场遗漏。发现问题的表述遵守 `core-role.md`：先引导、给"最小修复"、四段式解释。**对零基础大一生，只扫与当前章节相关的项，不超纲吓唬。**

## 1. 未定义行为（UB）高发点

- **数组/字符串越界**：下标从 0 起，循环上界是否 `< n` 而非 `<= n`；字符数组存字符串是否留了 `\0` 的一格（`"hello"` 需 `char s[6]`）。
- **未初始化就用**：局部变量、累加器（求和 `sum`、求最大 `max`、计数 `count`）是否在循环前赋初值。
- **除零**：`/` 与 `%` 的除数是否可能为 0（尤其来自 `scanf` 的输入）。
- **返回局部数组地址**：函数里定义的数组指针传出后失效。

## 2. 指针安全

- **空指针/野指针**：指针是否先初始化（哪怕 `= NULL`）再解引用；`*p` 前 `p` 指向是否有效。
- **`scanf` 漏 `&`**：读入标量是否 `&x`（数组名/字符串例外）。漏 `&` 是零基础最常见崩溃点。
- **`&` 与 `*` 混用**：取地址与解引用是否用反。
- 讲指针与内存时按 `core-role.md` 用 ASCII/Mermaid 画内存布局。

## 3. 格式说明符与类型匹配

- `%d`↔`int`，`%f`↔`float/double`（`scanf` 的 `double` 要 `%lf`），`%c`↔`char`，`%s`↔字符数组/`char*`，`%ld`↔`long`，`%u`↔`unsigned`，`%o`/`%x`↔八进制/十六进制。
- **`%d` 打印 `long`**（Windows 下 `long` 与 `int` 同为 4 字节暂安全，但口径要讲清）；`float` 运算是否理解有效位数。

## 4. 输入输出与流程

- **`scanf` 不检查返回值**：读取失败/类型不符时变量是垃圾值——教学阶段先提醒"读不到先看输入格式对不对"。
- **残留换行坑**：`scanf("%d",&n)` 后紧跟 `getchar()`/`scanf("%c")` 会读到回车。
- **`scanf` 卡住**：运行方式不支持标准输入时改用终端运行（见 `core-role.md` 常踩的坑）。
- **`if`/`while` 后误加 `;`**：`if(x);{...}` 使分支空转。
- **`=` 与 `==` 混淆**：条件里写成了赋值。
- **整数除法陷阱**：`10/3` 得 3 非 3.33；要小数需 `10.0/3` 或强制转换。

## 5. 语法与编译

- 缺 `;`、括号/引号不配对、中文标点（，""；）混进代码——零基础极常见。
- 函数缺返回类型 / 有返回却漏 `return`。
- 用了 `conio.h`/`getch()`/`clrscr()`/`system("pause")`（非标准、现代 gcc 不支持，见 `core-role.md`）。
- 源文件是否 UTF-8（否则中文注释/输出乱码）。

## 6. 边界与循环

- 循环变量方向/边界（`i++` 还是 `i--`、`<` 还是 `<=`）；`for` 三分号是否写全。
- 浮点比较用 `==` 不可靠，教学阶段讲"用 `fabs(a-b)<1e-6`"的思路即可，不展开 ULP。
