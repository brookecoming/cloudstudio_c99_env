# 教材例题代码规范（编辑 .c/.h 时生效）

为谭浩强教材例题（`0_textbook_code/` 下所有文件尤其适用）生成/修改 C 代码时的红线，全部遵守：

## 语法与风格

- **只用课本语句，禁 `goto`/标号**：循环用 `while`/`for`，多分支用 `if—else if—else`；绝不出现 `goto`、`loop:`、`next:`。算法里"返回 S2/S3"这类描述一律翻译成 `while`（当型循环），注释保留与 S1~Sn 的对应。课本从不出现 `goto`，且它是 C 明确不推荐的写法，会误导零基础学生。
- **一切以课本为准**：变量定义、数据结构、算法步骤严格贴合教材表述与记号，不擅自发挥、不引入课本/算法里根本没有的步骤或写法。拿不准回课本核对，不按"工程习惯"自由发挥。

## 屏幕输出一律英文/ASCII（红线）

- 凡 `printf` 打印到控制台的内容（含提示语、结果标签）**一律英文/ASCII，不得在字符串里写中文**。原因：源文件 UTF-8，而 Windows 控制台默认 GBK(936)，打中文会乱码（出现"渭嶙"这类）。英文在 Windows/Linux/Cloud Studio 全平台一致不乱。
- 中文讲解只留在代码注释与 Markdown。学生坚持要屏幕显示中文时，提示其自行开 Windows Beta UTF-8 区域设置或改用英文输出，**不主动引入 `windows.h`/`SetConsoleOutputCP`**（超纲）。

## 按题目数据模型定义变量，输入与处理输出解耦（红线）

- **先照"题目的数据模型"定义变量，再谈结构**。判据：题目用**带下标记号**描述"一批同类数据"（如例 2.2 的 n₁…n₅₀、g₁…g₅₀"都是已知的"），本质是"先有一批已知数据、再遍历处理"，应落地为**数组**（如 `id[]`/`g[]`），且"输入/准备数据"与"处理/输出"分成**独立阶段/循环**。
- **严禁**把一批数据退化成单个标量变量在循环里 `scanf` 现读现用（造成输入输出高度耦合、丢了数据模型）；**严禁**添加算法步骤里根本没有的"输入"步骤。数组虽为第 6 章内容，但作为 g_i 记号的正确归宿，用于演示恰当且更贴近课本。（源于例 2.2 首版误用"边读边判"单循环的教训。）

## 注释中文要通顺、像讲课稿（红线）

- 中文注释（解题思路、关键知识点、难点、易错点）是给零基础学生看、也是老师照着讲的稿子：**语言连贯、符合中文日常表达、一读就懂**，把一件事讲清比字数少更重要。
- **严禁**为求简短把话说得拗口、生造压缩短语、大量省略主语/连接词、堆括号嵌套、用"→/即/系/该"压成电报体。可用生活化类比和"也就是说、换句话说、注意、这里"等口语连接词。
- **分行**：按"一句完整话（一个完整意思）写在一整行"，**绝不为凑列数（如 80 列）在句中间手动断开**——中文双宽字符按字符数折行反而更宽且拦腰截断。长行交给编辑器软换行（Soft-Wrap，机房/投影见根目录 `投影建议.md`）。代码语句仍保持简短，只有注释允许长句。

## 源码末尾必附【讲解过程稿】（红线）

放在源码最末尾的第一人称口播稿，**骨架照搬课本该例题实际出现的小标题顺序**，把六拍讲法填进对应块，绝不逐行念代码。

- **求解型**（例 3.1/3.2/3.3/3.8 等）＝**解题思路**（说清题意＋整体大思路，复杂题的算法/N-S 图归这块、**不另立"设计算法"标题**）→ **编写程序**（按逻辑块逐块讲"在干嘛、为什么这么写"）→ **运行结果**（当堂对答案）→ **程序分析**（最该强调的一处/易错点，写到"学生搜不到"的层次）。
- **验证型**（例 3.6/3.7 等）＝课本只给一句题干就上代码，**跳过"解题思路"**，从**编写程序** → **运行结果**（观察现象是本页核心）→ **说明**（点破为什么出这个结果）。
- **绝不给课本没有的步骤硬造小标题。**
- **首尾**：最前一句开场点破本题要害（不装腔不报幕、不设悬问）；最后收尾一句总结＋抛一个学生此刻答得出的提问并当堂揭晓。
- **配套三要求**：①**互动停顿**——开场点破后的验证提问与收尾提问处加【互动停顿：停 2~3 秒…】标记；②**配图旁挂**——每例题配同目录 `liX.Y.puml`，`.c` 内不内嵌图、只放一行指路注释（如"见同目录 liX.Y.puml"），图只在 `.puml` 存一份（CMake 只 GLOB `*.c`，`.puml` 不影响构建）；③**去教师腔、师生共读**——学生也会看源文件，严禁"（老师上课可直接照着讲的口播稿）""讲课时可逐条说"这类只给老师看的 meta 注释，板块标题保持中性（如"关键知识点（对应课本"程序分析"）"）。
- 完整口播"三不一破"见 `lecture-script.md`。

## 代码转录与展示必核对运算符（红线）

把例题代码抄入源文件/PPT/讲义时，**逐个核对 `*` `+` `-` `/` 括号等符号完整未丢**（OCR、复制粘贴极易丢乘号减号，如 `b*b-4*a*c` 错抄成 `b-b-4-a c`、`p-q` 错抄成 `p q`）。**最终以 `gcc -std=gnu17` 编译通过为校验**——编译过了才允许展示/印发。

## 编译口径提示

概念/表格结论（字节数、有效数字、数值范围、常量类型判定）用 **VC++ 口径**；上机实际运行结果值以 **本机 GCC 实测**为准，两者不一致时如实记录实测值并点破"换编译器/精度结果就变"。详见 `vc-vs-gcc.md`。
