# 编译口径分工：讲课用 VC++，上机跑用 GCC（红线）

谭浩强《C 程序设计》（第 5 版）**全篇以 Visual C++（VC++6.0）为默认环境**——表 3.4 明标"Visual C++ 环境下"、`long double` 按 8 字节、整型常量按 4 字节判定等，都是 VC++ 口径。据此分两条线，**不得混写**：

## 讲课本 / 对考试 / 上 PPT → VC++ 口径

凡"讲课本、对考试、上 PPT"的内容——课件图、口播稿、PPT 备注、提词本里的**概念/表格结论**（字节数、有效数字、数值范围、常量类型判定等）——**一律用 VC++ 口径**，与课本表 3.4、正文一致。

措辞说"**课本（VC++）**"，不说"咱们用的 VC++"（机房其实跑 GCC）。

## 上机实际编译运行 → 本机 GCC 实测

凡"上机实际编译运行"的内容——`.c` 源码、`printf` 打印出来的**运行结果值**、编译报错、代码注释里的实测数据——**一律以本机 GCC 实测为准**（CLion / Code::Blocks / VS Code 只要配 MinGW，底下都是 `gcc -std=gnu17`）。

## 两者不一致时（典型：例 3.7）

例 3.7 `float` 打 `10000/3`：GCC 实测 `3333.333252` vs 课本 VC++ 印 `3333.333333`。

**如实记录 GCC 实测值**，并在注释里点破"换编译器/精度不同结果就变"——这本身就是"精度是硬件与编译器定的、别死记"的活教材。**绝不为凑课本 VC++ 的印刷值而篡改实测输出。**
